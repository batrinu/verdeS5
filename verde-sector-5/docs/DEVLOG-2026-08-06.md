## Redeploy runbook

**Frontend** (from `verde-sector-5/web-dashboard`):
```bash
npm run build
npx wrangler pages deploy dist --project-name verde-sector-5 --branch main --commit-dirty true
```
After deploying, the PWA service worker caches the old bundle — to verify the
new one in a browser you must unregister the SW + clear caches, then hard reload.

**Backend** (from `verde-sector-5/cloudflare-backend`):
```bash
npx wrangler d1 migrations apply verde-sector-5-db --remote   # if migrations changed
npx wrangler deploy
```

**Local dev**: frontend `npm run dev` (:3000). Backend `npm run dev` = `wrangler dev`
(:8787), Miniflare-simulated D1/R2. The dashboard works without the backend
(seed fallback); only live data needs wrangler running.

## Key decisions

- **Blob photos now, R2 later.** Watering proof photos are compressed client-side
  and stored as data-URL blobs directly in D1 (`watering_logs.photoProof`). R2 is
  not enabled on the account, and photos are the only thing that needed it. All
  persistence goes through one seam (`src/lib/photoStore.ts`) so the R2 swap is a
  single function change. Full plan in `photo-storage.md`.
- **One dark design language, everywhere.** The "Modern Earth Forest" dark theme
  (tokens in `web-dashboard/src/index.css`: `--bg-surface`, `--color-primary-*`,
  `--border-color`; Bricolage Grotesque display + Inter body) is now applied to
  every surface including modals and the Leaflet map popup. The biggest quality
  win was killing the white-modal-in-a-dark-app seam.
- **Honest offline handling.** Instead of silently falling back to local data, a
  persistent "Mod offline" banner shows when the API is unreachable, and write
  actions (adopt/water/alert) confirm success or say "Salvat local" on sync
  failure. `isApiReachable()` in `services/treeApi.ts` is the single source.
- **Plain language over jargon.** All user-facing copy is plain Romanian — no
  "Cloudflare / R2 / Simulator AI / Mock" leaking into the UI.
- **Presenter toggle demoted.** The Cetățean/Consiliu switch is a demo control,
  so it's visually quiet, labelled "Prezentare", and bound to the `P` key.

## Gotchas & lessons (the time-savers)

1. **`.gitignore` `lib/` hid the backend's `src/lib`.** A Python-template
   `lib/` rule silently untracked `cloudflare-backend/src/lib/` — including
   `prisma.ts` that `index.ts` imports. A fresh clone couldn't build. Fixed with a
   scoped negation. Lesson: when a stock `.gitignore` template meets a `src/lib`
   folder, check `git check-ignore`.
2. **wrangler.toml shipped with `database_id = "local"`.** That's a dev
   placeholder, not a real D1 — the backend had never actually been deployed. Had
   to `d1 create` a real DB and paste the id before `wrangler deploy`.
3. **R2 is not enabled** on the account (`wrangler r2 bucket create` → error
   10042). Commented out the `[[r2_buckets]]` binding to unblock; re-enable when R2
   is turned on in the dashboard.
4. **CORS must list the Pages origin.** The Worker's CORS allowlist didn't include
   `https://verde-sector-5.pages.dev`; add new front-end origins there.
5. **Worker 403s the default `Python-urllib` user-agent.** Cloudflare's edge bot
   protection blocks it — API smoke tests must send a browser UA.
6. **Transient toasts race with React StrictMode's double-mount.** A toast pushed
   from a mount-time effect never painted (the first mount's state was discarded).
   User-action toasts are fine; for load-time status use a **persistent indicator**
   (the offline banner), not a toast.
7. **The classic flexbox modal-clip bug.** An overlay with `align-items: center` +
   `overflow-y: auto` makes a modal taller than the viewport unreachable at the
   top. Fix: `align-items: flex-start` + child `margin: auto` + safe-area padding,
   so it centers when it fits and scrolls when it doesn't.
8. **PWA cache masks deploys.** Always unregister the service worker + clear caches
   before trusting what a browser shows post-deploy.
9. **Leaflet marker a11y + XSS.** Markers default to `alt="Marker"` — set a
   descriptive `alt`/`title`. And escape user-derived values (adopter name,
   nickname) before they go into popup `innerHTML`.

## Pitch walkthrough — incentives & sponsors (2026-08-06)

A 10-step demo script for presenting the incentives-and-sponsors feature set:

1. **Map thirst colors.** Open the map — trees are colored by thirst level
   (green → amber → red), so the audience sees at a glance which ones need
   water without opening anything.
2. **Select a thirsty tree.** Click a red/amber marker; the detail panel shows
   its status (species, thirst, last watering) and its impact stats (total
   liters, waterings, guardians).
3. **Water it.** Submit a watering — a tree message appears (personality
   flavor text) and EcoPuncte are awarded, with a toast confirming the write
   succeeded (or "Salvat local" if offline).
4. **Guardian card progress.** Open the citizen's guardian card — points
   total, level/progress bar, and adopted trees are visible in one place.
5. **Challenge widget.** Show the active challenge (e.g. "Augustul Udărilor")
   with progress toward the goal and the reward tied to completing it.
6. **`/community` boards.** Switch to the community leaderboard — top
   guardians by points, reinforcing the competitive/social loop.
7. **`/rewards` — redeem a voucher.** Spend EcoPuncte on a reward from a
   sponsor (e.g. Bicicleta Albastră) to show the points economy has a payout,
   not just a counter.
8. **`/sponsors` tiers.** Show the sponsor directory — GOLD/SILVER/BRONZE
   tiers (Solaris Energia, Panifica București, Bicicleta Albastră) and what
   each sponsors.
9. **Solaris grove.** Drill into "Crângul Solaris — Parcul Izvor" to show a
   sponsor's branded grove of real trees (tr_4/tr_5) tied to their campaign.
10. **ESG dashboard + CSV download.** Open the sponsor ESG dashboard and
    export the impact data as CSV — the tangible deliverable a sponsor takes
    away from the pitch.

**Offline fallback:** every step above works with the backend Worker fully
down. The frontend's seed data (`gamificationSeedData`, tree/service seed
fallbacks) covers trees, sponsors, groves, challenges, and rewards, and
`isApiReachable()` swaps to it automatically with an honest "Mod offline"
banner — so the walkthrough is safe to run with no network at all.

### Future work

- **Anti-abuse for points farming.** No guard yet against rejoin/rewater
  loops (adopt → water → un-adopt → re-adopt the same tree, or rapid repeat
  waterings) to farm EcoPuncte. Needs a cooldown or server-side rate limit
  before real rewards are at stake.
- **R2 photo migration.** Watering proof photos are still data-URL blobs in
  D1 (`watering_logs.photoProof`); see "Blob photos now, R2 later" above and
  `photo-storage.md` for the swap plan once R2 is enabled on the account.
- **Sponsor auth.** The sponsor dashboard has no login/access control yet —
  anyone can view any sponsor's ESG data. Needs real auth before sponsors are
  real (non-demo) tenants.
- **Real reward fulfillment.** Voucher redemption currently just deducts
  points and records the redemption; there's no fulfillment pipeline (code
  generation, delivery, sponsor notification) behind it.
- **Dark-launched endpoints.** `/api/v1/leaderboard`, `/api/v1/rewards/:id/redeem`,
  and `/api/v1/sponsors/:slug/dashboard` exist on the backend but aren't called
  yet — the frontend still renders those views from seed data/localStorage.
